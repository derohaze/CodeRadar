A finding that disappears between detection and fix might as well never have existed. Handoffs leak: chat scrolls, PR comments resolve, spreadsheets rot.

CodeRadar is built to keep findings visible in one surface, from quoted evidence to applied fix.

## Every finding keeps its context

| Team question | CodeRadar focus |
| --- | --- |
| Where is it? | File plus line range, quoted in place. |
| How bad is it? | Severity plus confidence, ordered by priority. |
| Why should I care? | Consequence if it ships, spelled out. |
| How do I fix it? | Concrete fix plus agent-ready prompt. |
| What was rejected? | Dropped candidates with reasons, still listed. |

CodeRadar connects these responsibilities so that a finding does not disappear when it moves between detection, triage, fixing, and verification.

## The CodeRadar outcome

A finding should not become harder to manage just because the codebase is growing. CodeRadar is built to make review work visible, structured, and easier to trust.
